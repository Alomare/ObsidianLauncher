## 打包 {#packing}

压缩模组文件夹，使 `obsidian.json` 位于压缩包顶层，或位于顶层的一个文件夹中。玩家把 `.zip` 拖到模组列表上，安装就完成了。

不要包含模组用不到的文件。`obsidian.json` 中的路径应相对于模组文件夹，并使用正斜杠。

## 版本 {#versions}

使用 `1.4.2` 这样的版本号：

- 修复问题时提高最后一位；
- 增加新功能和选项时提高中间一位；
- 当模组的变化是玩家在更新前会想知道的，提高第一位。

导入更高版本的玩家会保留选项值和按键，类型发生变化的选项除外。请在各个版本之间保持选项和按键的 id 不变。

> [!WARNING]
> 永远不要更改已发布模组的 `id`。Obsidian 会把它视为另一个模组，玩家最终会同时拥有两个。

## 更新 {#updates}

在 `obsidian.json` 中指定 GitHub 仓库后，玩家可以在应用中更新：

```json
"source": "https://github.com/author/mod"
```

每次发布新版本时：

1. 提高 `obsidian.json` 中的 `version`。
2. 创建一个以该版本为标签的 GitHub 发布版本，例如 `v1.4.2`。
3. 把 `.zip` 附加到发布版本。如果发布版本中有多个文件，请在正确的那个文件名中写上模组 id，例如 `author.mod-name-1.4.2.zip`。

Obsidian 只把稳定版作为更新提供，并跳过草稿。它会拒绝 id 不同或版本不更高的 `.zip`。

### 渠道 {#channels}

预发布版本（例如 `1.5.0-beta.1`）属于以预发布部分第一个词命名的渠道：这里是 `beta`。模组详情中的版本标签页在**稳定版**旁为每个渠道列出一个标签页，并可以从那里安装任意版本。在 GitHub 上标记为预发布、但版本号是普通版本的发布版本，归入名为 `pre` 的渠道。`ci` 渠道是隐藏的，用于工作流生成的测试版本。

列在 Store Index 中的私有仓库模组属于抢先体验：只有 GitHub 账号能读取该仓库、并且允许了私有仓库权限的玩家才能在商店中看到它（[账户](wiki:tab-account)）。

## 图片 {#pictures}

添加一张方形的 `image.png`（或 JPG、WebP，最大 4 MB），并在 `obsidian.json` 中用 `"image": "image.png"` 指定。512 × 512 像素就足够了。

## 翻译 {#translations}

- 在 `name`、`description` 和 `label` 中提供所有可用语言的名称、描述和选项标签。
- 把模组在游戏中显示的文字放在 `locales/<语言>.json` 中。
- 英文始终是后备，所以缺少的翻译会显示英文，而不是空白。

## 发布之前 {#before-you-release}

1. 把 `.zip` 本身（而不是文件夹）导入 Obsidian，测试玩家实际得到的内容。
2. 部署，玩一场任务，并阅读模组的日志。
3. 对于会话模组，与一位没有运行它的朋友一起测试：模组应该会关闭（[编写会话模组](wiki:session-mods)）。
4. 在描述中写明模组改变了什么，以及其他玩家是否会注意到。
