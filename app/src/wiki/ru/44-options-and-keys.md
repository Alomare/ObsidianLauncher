Параметры появляются на панели справа, когда игрок выбирает мод. Obsidian проверяет каждое значение по объявлению, поэтому мод никогда не получит значение вне объявленного диапазона. Значения принадлежат профилю, поэтому два профиля могут запускать один мод с разными настройками.

## Объявление параметров {#declaring-options}

У каждого параметра есть `id` (строчные латинские буквы, цифры и `_`), `type`, `default` и `label`. `description` добавляет текст, который игроки видят при наведении на параметр.

| Тип | Значение | Дополнительные поля |
|---|---|---|
| `toggle` | `true` или `false` | |
| `number` | число | `min`, `max`, `step` |
| `choice` | один из перечисленных id | `choices`: список id или объектов `{ "id": "…", "label": { … } }` |
| `key` | имя клавиши, например `f8` | |
| `color` | `#rrggbb` | |

```json
"options": [
  { "id": "enabled", "type": "toggle", "default": true, "label": { "en": "Show the compass" } },
  { "id": "style", "type": "choice", "default": "small",
    "choices": [ { "id": "small", "label": { "en": "Small" } }, { "id": "large", "label": { "en": "Large" } } ],
    "label": { "en": "Size" }, "visible_when": { "enabled": true } },
  { "id": "tint", "type": "color", "default": "#f0b429", "label": { "en": "Color" }, "scope": "client" }
]
```

### Показывать параметры только когда они важны {#showing-options-only-when-they-matter}

`visible_when` скрывает параметр, пока другие параметры не примут перечисленные значения. В примере выше **Size** показывается только при включённом **Show the compass**.

### Личные параметры в сессионных модах {#personal-options-in-session-mods}

Значения параметров сессионного мода или расширения учитываются, когда Obsidian сравнивает моды двух игроков, ведь ползунок баланса меняет общую игру. Помечайте параметр `"scope": "client"`, если значение меняет только то, что видит этот игрок, например цвет или расстояние камеры. Тогда игроки могут выбирать разные значения и всё равно совпадать ([Игра по сети](wiki:multiplayer)).

### Параметры в дополнительной области {#options-in-a-secondary-scope}

В моде с [гибридными областями](wiki:manifest#hybrid-scopes) `"secondary_scope": "<id>"` помещает параметр в эту дополнительную область. Параметр дополнительной клиентской области считается как `"scope": "client"`, а параметр выключенной области не учитывается вовсе. В сессионном моде параметр без пометки следует самой строгой из включённых дополнительных областей. Переключатель, который дополнительная область указывает в `option`, включает и выключает её, поэтому его изменение требует применения.

## Группы параметров {#option-groups}

`option_groups` распределяет параметры по сворачиваемым заголовкам. Каждый параметр указывает заголовок через `group`:

```json
"option_groups": [
  { "id": "idle", "label": { "en": "Idle crosshair" }, "description": { "en": "While not aiming." } },
  { "id": "aim", "label": { "en": "Aiming" }, "collapsed": true }
],
"options": [
  { "id": "idle_shape", "type": "choice", "default": "cross", "choices": ["cross", "dot"], "group": "idle",
    "label": { "en": "Shape" } }
]
```

Сначала идут параметры без группы, затем каждая группа в объявленном порядке. `collapsed` делает группу изначально свёрнутой. Приложение запоминает, какие группы игрок раскрыл, для каждого мода. `visible_when` работает внутри групп так же, как везде. `group`, который не называет ни одну группу, отклоняется при импорте. Старый Obsidian игнорирует оба поля и показывает параметры как раньше.

## Превью параметров {#option-previews}

`option_previews` показывает изображение значений, нарисованное по файлу SVG из папки мода и перерисованное по мере изменения значений игроком:

```json
"option_previews": [
  { "id": "idle_preview", "group": "idle", "template": "preview/idle.svg", "width": 240, "height": 140,
    "label": { "en": "Preview" } }
]
```

Превью показывается вверху указанной группы или вверху вкладки Параметры. Файл должен быть в формате SVG, не больше 64 КБ, и проверяется при импорте. Внутри него:

- `{{expr}}` в значении атрибута или в тексте заменяется значением выражения.
- `data-if="expr"` на любом элементе удаляет элемент, пока выражение ложно.

В выражении можно использовать числа, `'текст'`, id параметров (число, `true` или `false`, id варианта или цвет `#rrggbb`), `+ - * / %`, `== != < > <= >=`, `&& || !`, `a ? b : c`, скобки и `min`, `max`, `abs`, `round`, `floor`, `ceil` и `clamp(x, lo, hi)`. `+` склеивает текст. Выражение с ошибкой не даёт ничего, а элемент, у которого в `data-if` ошибка, удаляется.

```xml
<svg xmlns="http://www.w3.org/2000/svg" width="240" height="140">
  <rect width="240" height="140" fill="#1b1d1f"/>
  <g data-if="idle_shape == 'cross'" stroke="{{idle_color}}" stroke-width="{{idle_thickness}}">
    <line x1="{{120 - idle_size}}" y1="70" x2="{{120 + idle_size}}" y2="70"/>
    <line x1="120" y1="{{70 - idle_size}}" x2="120" y2="{{70 + idle_size}}"/>
  </g>
  <circle data-if="idle_shape == 'dot'" cx="120" cy="70" r="{{idle_size / 2}}" fill="{{idle_color}}"/>
</svg>
```

Картинка показывается как изображение: скрипты, `foreignObject`, атрибуты `on...` и ссылки за пределы файла удаляются.

## Чтение параметров в Lua {#reading-options-in-lua}

```lua
local get = obsidian.settings.get

if get("enabled") then
  local size = get("style")   -- "small" or "large"
end
```

`obsidian.settings.get` возвращает значение, выбранное игроком, или значение по умолчанию.

Изменённый параметр или клавиша попадает в игру при следующем запуске: Obsidian записывает их в файл настроек, который читает загрузчик, без применения. Следующим параметрам нужно применение, и в подсказке каждого написано **Вступает в силу после применения**:

- параметр, который выбирает файлы через `when` (ниже);
- переключатель, который включает [дополнительную область](#options-in-a-secondary-scope);
- параметр сессионного мода или расширения, который учитывается при сравнении наборов, то есть любой параметр без пометки `"scope": "client"` и вне дополнительной клиентской области;
- все параметры мода без скрипта `entry`.

## Параметры в меню паузы {#options-in-the-pause-menu}

Мод, которому нужен Obsidian API, может показывать настройки и в игре, на странице в разделе **Mods** меню паузы, через `api.mod_settings`. Строка, созданная с `option = true`, является параметром с тем же id из `obsidian.json`: она начинает со значения из приложения, а значение, изменённое в игре, возвращается в активный профиль, пока игра закрыта. Строки перечислены в [справочнике Obsidian API](https://github.com/Alomare/ObsidianAPI/blob/main/REFERENCE.md#your-settings-in-the-pause-menu-apimod_settings).

## Параметры, которые выбирают файлы {#options-that-pick-files}

Ресурс может зависеть от параметра через `when`. Ресурс попадает в игру, только пока параметры имеют эти значения:

```json
"resources": [
  { "type": "lua", "name": "lua/hud/compass", "source": "res/compass_small.lua", "when": { "style": "small" } },
  { "type": "lua", "name": "lua/hud/compass", "source": "res/compass_large.lua", "when": { "style": "large" } }
]
```

Изменение такого параметра требует нового применения.

## Клавиши {#keys}

Объявите каждую клавишу, которую слушает мод, со значением по умолчанию:

```json
"keybinds": [ { "id": "toggle", "default": "f8", "label": { "en": "Turn the compass on or off" } } ]
```

Затем реагируйте на неё в Lua:

```lua
obsidian.keybind("toggle", function()
  obsidian.log("toggle pressed")
end)
```

Функция вызывается один раз при каждом срабатывании привязки. Игроки переназначают клавиши в приложении, где и решаются конфликты между модами. Имена клавиш совпадают с игровыми, строчными буквами: `f8`, `k`, `insert`. Игрок может назначить и кнопку мыши, кроме левой: загрузчик читает `mouse_middle`, `mouse_right`, `mouse_extra_1` и `mouse_extra_2` с мыши.

### Режимы ввода {#input-modes}

Игроки также выбирают, как срабатывает каждая привязка, в окне **Изменить привязки** на вкладке Клавиши:

| Режим | Срабатывает |
|---|---|
| Нажатие (по умолчанию) | В кадре, когда клавишу нажали |
| Отпускание | В кадре, когда клавишу отпустили |
| Касание | Когда клавишу отпустили в течение четверти секунды |
| Двойное касание | При втором нажатии в течение 0,3 секунды после первого |
| Долгое нажатие | Один раз, после полусекунды удержания |

Режим применяет загрузчик, поэтому моду не нужен для этого код.

### Ввод с контроллера {#controller-input}

На вкладке Клавиши есть столбец для мыши и клавиатуры и столбец для контроллера. Если у действия есть и ввод с контроллера, объявите этот ввод как параметр `choice` и укажите параметр в `pad` привязки:

```json
"options": [ { "id": "pad_toggle", "type": "choice", "default": "thumbs",
               "choices": [ { "id": "thumbs", "label": { "en": "Both sticks pressed in" } }, { "id": "off", "label": { "en": "Off" } } ] } ],
"keybinds": [ { "id": "toggle", "default": "f8", "pad": "pad_toggle", "label": { "en": "Turn the compass on or off" } } ]
```

Тогда приложение показывает параметр в строке привязки, в столбце контроллера, и не показывает его на вкладке Параметры. Мод читает параметр как любой другой. Чтобы режим ввода работал и для контроллера, передайте в `obsidian.keybind` функцию, которая сообщает, удерживается ли ввод с контроллера, как `opts.pad`; тогда загрузчик вызывает `fn` с `"pad"`, когда он срабатывает (`obsidian.capabilities.input_modes` равен `true` в загрузчике, который так умеет). Иначе мод следит за контроллером сам.

Игроки могут дать любой привязке ввод с контроллера в окне **Изменить привязки**, с параметром `pad` или без него: от одной до четырёх кнопок, нажатых вместе. Тогда загрузчик сам читает контроллер для этой привязки и вызывает `fn` с `"pad"` вместо `opts.pad` (`obsidian.capabilities.pad_binds` равен `true` в загрузчике, который так умеет). Моду для этого код не нужен. У привязки без `pad` в этом столбце стоит прочерк. Версии Obsidian без столбца контроллера игнорируют `pad` и показывают параметр на вкладке Параметры.
