Obsidian API является модом, на котором строятся другие моды. Он находит объекты игры по именам, меняет их способами, которые игра принимает, и отменяет изменения, когда это нужно. Obsidian Trainer построен на нём и не использует ничего, что недоступно другим модам.

Эта страница даёт обзор. Каждый вызов с аргументами, ответами и примерами описан в [REFERENCE.md](https://github.com/Alomare/ObsidianAPI/blob/main/REFERENCE.md), который также лежит в папке Obsidian API в составе Obsidian Kit, где его может прочитать ИИ-инструмент, работающий над модом. Справочник написан на английском.

## Как подключить {#using-it}

Укажите его в `requires`, и Obsidian включит его вместе с модом и запустит первым:

```json
"scope": "session",
"entry": "main.lua",
"requires": ["obsidian.api"]
```

Затем получите его в скрипте:

```lua
local api = obsidian.import("obsidian.api")

obsidian.keybind("panic", function()
  api.player.heal()
  api.enemies.kill_near(20)
end)
```

## Клиентские и сессионные моды {#client-mods-and-session-mods}

Obsidian API является [библиотекой](wiki:session-mods#libraries), поэтому получает область модов, которым он нужен. Клиентский мод может его требовать и оставаться клиентским, без влияния на подбор игроков и Галактическую войну. Клиентский мод может читать что угодно, использовать то, что видит или слышит только этот игрок (`api.ui`, `api.map`, `api.audio` и `api.music`), и слушать `api.events`. Каждый вызов, который меняет общую игру, отвечает клиентскому моду `false, "needs_session"`.

В сессионном моде эти вызовы работают, пока в лобби есть разрешение. Когда разрешение пропадает, Obsidian API снимает эффекты и правки мода, а вызовы отвечают `false, "not_cleared"`. Когда разрешение возвращается, он восстанавливает их. Расширение получает все вызовы, пока идёт контент, и `false, "not_started"` вне его ([Как написать расширение](wiki:session-mods#expansions)).

## Как отвечают вызовы {#how-calls-answer}

Действия отвечают `true` или `false` и короткой причиной, например `"host_only"`, `"no_avatar"` или `"not_in_mission"`. Вызовы, которые что-то создают, например `api.bots.add`, возвращают созданное или `nil` и причину. Обычный отказ никогда не вызывает ошибку:

```lua
local ok, why = api.stratagems.call("stratagem_resupply", api.world.cursor())
if not ok then obsidian.toast("No resupply: " .. why) end
```

## Что в нём есть {#what-it-holds}

| Таблица | Для чего |
|---|---|
| `api.game` | Текущее состояние, локальный игрок, хост и безопасная запись защищённых значений |
| `api.lobby` | Игроки в лобби и короткие тексты, общие для всех компьютеров в нём |
| `api.catalog` | Оружие, стратагемы, перки, враги, техника и предметы по именам: основная игра и купленные игроком DLC |
| `api.edits` | Изменения таблиц настроек, проверенные и записанные, с отменой |
| `api.effects` | Изменения, которые сохраняются между возрождениями и миссиями, например бессмертие или скорость, и свои эффекты |
| `api.events` | Вызовы, когда игра сообщает об убийстве врага, гибели игрока, цели, стратагеме и другом |
| `api.player` | Здоровье, жизни, возрождение, телепортация, внешний вид и эффекты состояния |
| `api.gear` | Оружие, рюкзаки, перки, дроны и пополнение, а также характеристики одного оружия |
| `api.vehicles` | Техника, которой управляет игрок, ремонт и пополнение |
| `api.stratagems` | Перезарядка, число использований, вызовы и новые стратагемы на основе игровых |
| `api.enemies` | Поиск, создание, урон и удаление врагов, а также сила давления столкновений |
| `api.mission` | Цели, эвакуация, образцы, модификаторы Proving Grounds и завершение миссии |
| `api.combat` | Множители урона для игроков и врагов |
| `api.world` | Позиции, объекты сцены, камера, освещение, время суток и облик миссии |
| `api.map` | Карта миссии этого игрока: масштаб, метки и маркеры |
| `api.audio`, `api.music` | Громкость, звуки и саундтрек |
| `api.menu` | Внутриигровое окно, которое открывает **F6**, где у каждого мода своя папка страниц |
| `api.mod_settings` | Страница настроек мода в разделе **Mods** меню паузы игры ([Параметры в меню паузы](wiki:options-and-keys#options-in-the-pause-menu)) |
| `api.ui` | Подсказки, метки на карте, меню корабля и игровые тексты с другими словами |
| `api.progress` | Сохранение: образцы, открытия, улучшения и снаряжение |
| `api.console` | Команды разработчика игры, кроме тех, что обращаются к общему серверу |
| `api.bots` | Хеллдайверы под управлением этого компьютера, с приказами, снаряжением и помощью |
| `api.nav` | Пешие маршруты для ботов и модов |
| `api.capture` | Снимки экрана игры, сохраняемые как файлы изображений |

## Правила, которые стоит знать {#rules-worth-knowing}

Вызовы Obsidian API уже соблюдают эти правила. Они важны, когда мод обращается к таблицам и функциям игры в обход API:

> [!WARNING]
> Игра хранит хешированные копии защищённых значений, таких как `hitpoints_real`, `rounds`, `cooldown_timer`, `uses_left`, `num_grenades` и `extra_lives`. Прямая запись в одно из них запускает защиту игры от подделки, которая отключает игрока от сети до перезапуска игры. Используйте `api.game.protected` или команду в очереди. `api.edits` отклоняет эти ключи.

- Команда в очереди, которой игра не знает, или юнит, чей пакет не загружен, останавливают игру ошибкой, которую не может перехватить ни один скрипт.
- Таймер, который игра ведёт, пока он больше нуля, например `drop_time` десантной капсулы, никогда не заканчивается на 0. Используйте 0.01.
- Векторы игры живут только в том кадре, где созданы. Чтобы сохранить их, копируйте числа.
- Опыт и звание попадают в общие таблицы лидеров со следующими обычными результатами, даже после очистки.

Полный список приведён в REFERENCE.md.
