`obsidian.json` лежит в корне папки мода или в корне `.zip`. Obsidian проверяет его при импорте и сообщает, какое поле неверно, если что-то не так.

## Полный пример {#a-full-example}

```json
{
  "obsidian": 1,
  "id": "yourname.better-camera",
  "version": "1.2.0",
  "name": { "en": "Better Camera", "pt-BR": "Câmera Melhor" },
  "description": { "en": "A closer camera with a toggle key." },
  "authors": ["Author Name"],
  "image": "image.png",
  "scope": "client",
  "entry": "main.lua",
  "loader_api": 1,
  "options": [
    { "id": "distance", "type": "number", "default": 5, "min": 1, "max": 12, "step": 0.5,
      "label": { "en": "Camera distance" } }
  ],
  "keybinds": [
    { "id": "toggle", "default": "f8", "label": { "en": "Toggle the camera" } }
  ],
  "resources": []
}
```

## Поля {#fields}

| Поле | Обязательно | Что это |
|---|---|---|
| `obsidian` | да | Версия формата. Пока всегда `1`. |
| `id` | да | Постоянный id: от 1 до 64 символов из `a-z`, `0-9`, `.`, `_` и `-`, начиная с буквы или цифры. Используйте вид `yourname.mod-name`. |
| `version` | да | Номер версии, например `1.2.0` (семантическое версионирование). Более высокая версия заменяет более низкую при импорте. |
| `name` | да | Название мода по языкам. Английское (`en`) обязательно. |
| `description` | нет | Одно-два предложения по языкам, показываются под названием. |
| `authors` | нет | Список имён. |
| `image` | нет | Квадратный PNG, JPG или WebP в папке мода, до 4 МБ. |
| `source` | нет | Веб-адрес мода, показывается в подробностях. Репозиторий GitHub, например `https://github.com/author/mod`, также позволяет игрокам обновлять мод из приложения ([Как поделиться модом](wiki:sharing#updates)). |
| `scope` | нет | `client`, `session`, `expansion` или `library` ([Области](wiki:scopes)). Если поле отсутствует или неизвестно, мод считается модом без области и работает как клиентский, или как сессионный при `every_player`. |
| `every_player` | нет | `true` для мода, который работает, только когда его запускают все игроки в лобби ([Моды, нужные всем игрокам](wiki:session-mods#every-player)). Не для клиентских модов и расширений. |
| `secondary_scopes` | нет | Код, параметры и файлы, которые работают с областью, отличной от `scope` ([Гибридные области](#hybrid-scopes)). Не для библиотек. |
| `entry` | нет | Скрипт Lua, который запускает загрузчик. Моды, которые только заменяют файлы игры, его не указывают. |
| `modules` | нет | Дополнительные файлы `.lua` помимо `entry`, которые мод загружает через `obsidian.module`. Пути внутри папки мода. |
| `requires` | нет | Id модов, нужных этому моду. Включение мода включает их, и они запускаются раньше. Игроки видят их на вкладке Зависимости мода. Применение останавливается с сообщением, если какого-то не хватает. |
| `load` | нет | Место, которое мод просит в порядке загрузки: `"first"`, `"last"` или объект с дополнительными просьбами ([Просьбы о порядке загрузки](#load-order-requests)). |
| `load_after` | нет | Id модов, после которых этот мод просит загружаться. То же, что `after` внутри `load`, оставлено для модов, написанных раньше. |
| `loader_api` | нет | Версия [Loader API](wiki:loader-api), нужная моду. `1`, если не указано. |
| `min_obsidian` | нет | Самая старая версия Obsidian, с которой работает мод, например `"1.1.0"`. Более старая отказывается от мода и просит игрока обновиться. Obsidian до 1.1 это поле не читает. |
| `options` | нет | Настройки, которые игроки меняют в приложении ([Параметры и клавиши](wiki:options-and-keys)). |
| `option_groups` | нет | Сворачиваемые заголовки для группировки параметров ([Группы параметров](wiki:options-and-keys#option-groups)). |
| `option_previews` | нет | Изображения значений параметров по шаблонам SVG ([Превью параметров](wiki:options-and-keys#option-previews)). |
| `keybinds` | нет | Клавиши, которые игроки могут переназначить в приложении. `pad` привязки называет параметр-выбор с кнопками контроллера для того же действия ([Ввод с контроллера](wiki:options-and-keys#controller-input)). |
| `resources` | нет | Файлы игры, которые мод заменяет или добавляет ([Замена файлов игры](wiki:resources)). |
| `save_editor` | нет | Что мод показывает на вкладке Моды [редактора сохранений](wiki:saves) ([Редактор сохранений](#save-editor)). |

## Просьбы о порядке загрузки {#load-order-requests}

`load` принимает просто `"first"` или `"last"` либо объект с любыми из этих полей:

```json
"load": {
  "position": "last",
  "before": ["author.other-mod"],
  "after": ["author.base-mod"],
  "after_patches": true
}
```

| Поле | О чём просит |
|---|---|
| `position` | `"first"` для начала порядка загрузки, `"last"` для конца. |
| `before` | Id модов, перед которыми загружается этот мод. |
| `after` | Id модов, после которых загружается этот мод, чтобы он побеждал в файлах, которые заменяют оба. |
| `before_patches` | `true`, чтобы загружаться перед всеми модами, заменяющими файлы игры (у которых есть `resources`). |
| `after_patches` | `true`, чтобы загружаться после всех модов, заменяющих файлы игры. |

Новый мод занимает запрошенное место, когда добавляется в профиль. После этого действует порядок, заданный игроком, пока он не нажмёт **Сортировать моды** на вкладке Моды ([Сортировка модов](wiki:load-order#sort-mods)), что перемещает только нуждающиеся в этом моды. Id модов, которых у игрока нет, пропускаются, и Сортировать моды сообщает об этом.

Просите только то, что моду нужно. Два мода, которые оба просят загружаться последними или просят загружаться после друг друга, не могут получить своё: Сортировать моды оставляет их на месте и предлагает игроку расставить их вручную.

Obsidian проверяет `load` при импорте: отклоняются позиция, отличная от `first` или `last`, неизвестное поле, id самого мода и один и тот же id в `before` и `after`. Obsidian 1.3.1 и более ранние читают только `"last"` и показывают мод с любым другим `load` как нечитаемый.

## Гибридные области {#hybrid-scopes}

`scope` является основной областью мода. `secondary_scopes` перечисляет области, с которыми вместо неё работает часть кода, параметров и файлов, каждая `client` или `session` ([Гибридные области](wiki:scopes#hybrid-scopes)). Сессионный мод использует их, чтобы личный код продолжал работать в лобби без разрешения; расширение использует дополнительную сессионную область для кода, который работает и вне контента, в лобби с разрешением.

```json
"scope": "session",
"secondary_scopes": [
  { "id": "view", "scope": "client",
    "name": { "en": "Camera and view" }, "description": { "en": "Keeps working in any lobby." } },
  { "id": "weapon_range", "scope": "session", "option": "max_weapon_range",
    "name": { "en": "Max weapon range" } }
]
```

| Поле | Что это |
|---|---|
| `id` | Строчные латинские буквы, цифры и `_`, как у id параметра. |
| `scope` | `client` или `session`. |
| `name`, `description` | Текст по языкам, показывается в подробностях мода и во внутриигровом уведомлении. |
| `option` | Параметр-переключатель мода. Дополнительная область включена, только пока включён этот параметр, и его изменение требует применения. |

Код, параметры и файлы указывают свою дополнительную область: `opts.secondary_scope` в [Loader API](wiki:loader-api#hybrid-scopes), `secondary_scope` у [параметра](wiki:options-and-keys#options-in-a-secondary-scope) и у [ресурса](wiki:resources#hybrid-scopes). В сессионном моде всё без пометки следует самой строгой из включённых дополнительных областей; в расширении остаётся с расширением. Выключенная дополнительная область не запускает код, не применяет файлы и не учитывается при сравнении у игроков.

Основную область читает старый Obsidian и запускает с ней весь мод, поэтому указывайте там самую строгую: `session` для сессионного мода с дополнительной сессионной областью, `expansion` для расширения. Obsidian отклоняет повторяющийся id, область, отличную от `client` или `session`, дополнительную сессионную область при основной области, отличной от `session` или `expansion`, `option`, который не является переключателем, и пометку `secondary_scope`, которая не называет ни одну из областей. Obsidian 2.0.0-beta.1 и более ранние читают тот же список под именем `parts`, с пометкой `part`; Obsidian по-прежнему читает эти имена.

## Текст на нескольких языках {#text-in-several-languages}

Каждое поле, которое читают игроки, является объектом с записью для каждого языка, например `en`, `pt-BR`, `ru` и `zh-CN`, языков приложения. Английский обязателен всегда и подставляется вместо любого отсутствующего языка.

Текст, который мод показывает в игре, лежит в папке `locales` рядом с `obsidian.json`, по файлу на каждый язык игры (`locales/en.json`, `locales/fr.json` и так далее), и каждый файл является простым объектом из ключей и текстов. Мод читает их через `obsidian.text`, где перечислены имена файлов ([Loader API](wiki:loader-api#obsidian-text-key)).

## Редактор сохранений {#save-editor}

`save_editor` добавляет раздел мода на вкладку Моды [редактора сохранений](wiki:saves), для песочниц. Значения хранятся в данных, которые мод читает через [`obsidian.save_data`](wiki:loader-api#save-data), под id мода.

```json
"save_editor": {
  "items": [
    { "type": "stratagem", "name": "my_strike", "label": { "en": "Orbital Strike" }, "unlock": "manual" },
    { "type": "weapon", "name": "my_rifle", "label": { "en": "Long Rifle" }, "unlock": { "rank": 10 } }
  ],
  "fields": [
    { "id": "difficulty", "type": "choice", "label": { "en": "Difficulty" }, "choices": ["easy", "hard"] },
    { "id": "boost", "type": "number", "label": { "en": "Boost" }, "min": 0, "max": 5, "when": { "difficulty": "hard" } },
    { "id": "enabled", "type": "toggle", "label": { "en": "Enabled" } }
  ]
}
```

`items` перечисляет то, что мод добавляет в игру. `type` равен `stratagem`, `weapon` или `perk`, а `unlock` говорит, как сохранение получает предмет: `"manual"` показывает переключатель, `"free"` и `"base"` означают, что предмет есть в каждом сохранении, а `{ "rank": n }` означает, что он выдаётся с этим званием.

`fields` являются значениями, которые игрок может менять. `type` равен `number` (с `min` и `max`), `toggle` или `choice` (с `choices`, где каждый вариант является id или объектом с `id` и `label`). `when` делает поле серым, если указанные поля не имеют указанных значений.

Пока мод выключен, раздел серый, а данные остаются в сохранении. Если мод уходит из библиотеки, данные перечисляются под id мода, чтобы игрок мог их удалить. `"type": "tree"` зарезервирован на будущее.

## Поля, которых Obsidian не знает {#fields-obsidian-doesn-t-know}

Неизвестные поля сохраняются и игнорируются, поэтому мод, написанный для более поздней версии Obsidian, всё равно импортируется.
