Obsidian Loader запускает скрипт `entry` каждого включённого мода в порядке загрузки, один раз, при запуске игры. Каждый скрипт видит глобальную таблицу `obsidian`. Всё, что мод регистрирует через неё, работает под защитой: ошибка записывается в журнал и никогда не останавливает игру.

## Хуки {#hooks}

### obsidian.hook(target, method, fn, opts)

Оборачивает функцию игры. `target` является таблицей или именем глобальной таблицы в виде строки. `fn` получает сначала исходную функцию, затем аргументы вызова:

```lua
obsidian.hook("PlayerUnitMovement", "update", function(original, self, dt)
  -- before the game code
  local result = original(self, dt)
  -- after the game code
  return result
end)
```

Если глобальной таблицы ещё нет, хук ждёт и ставится, как только игра её определит. Если `fn` даёт сбой, вместо неё выполняется исходная функция.

В сессионном моде хук вызывает только исходную функцию, пока в лобби нет разрешения ([Как писать сессионные моды](wiki:session-mods)). В расширении он вызывает только исходную функцию, пока не начнётся контент ([Как написать расширение](wiki:session-mods#expansions)). `opts.secondary_scope` помещает хук в [дополнительную область](#hybrid-scopes) мода.

### obsidian.wrap(target, method, fn)

То же, что `obsidian.hook`, с той же защитой при сбое `fn`, но продолжает работать, пока в лобби нет разрешения, и вне контента расширения. Предназначено для входа в расширение и для мода, чьи заменённые файлы тоже нельзя отключить, где выключение хука оставило бы игру наполовину изменённой. Всё остальное должно использовать `obsidian.hook`. В старом загрузчике проверяйте `obsidian.capabilities.wrap`.

### obsidian.on_require(name, fn)

Вызывает `fn(module)`, когда игра загружает скрипт `name`, например `"lua/settings/perk_settings"`. Используйте, чтобы изменить таблицу настроек сразу после того, как игра её построит. Если скрипт уже загружен, `fn` выполняется сразу.

### obsidian.on_frame(fn, opts)

Вызывает `fn` раз в кадр. Верните `true`, чтобы прекратить вызовы. Функции кадра сессионного мода работают только в лобби с разрешением, а функции расширения только пока идёт контент. `opts.secondary_scope` помещает функцию в [дополнительную область](#hybrid-scopes) мода. `opts.always` запускает её в любом лобби, как `obsidian.wrap` делает с хуком, для работы, которую видит только этот игрок; сначала проверьте `obsidian.capabilities.secondary_scopes`, так как старый загрузчик управляет ею по-прежнему.

### obsidian.after_startup(fn)

Вызывает `fn`, когда все моды запустились, чтобы моды могли работать вместе, не завися от порядка загрузки.

## Настройки и клавиши {#settings-and-keys}

### obsidian.settings.get(id, mod_id)

Значение параметра `id` этого мода: выбранное игроком в приложении или значение по умолчанию ([Параметры и клавиши](wiki:options-and-keys)). Скрипт игры, который заменяет мод, выполняется вне мода, поэтому там передавайте id мода как `mod_id`.

### obsidian.keybind(id, fn, opts)

Вызывает `fn(device)` при каждом срабатывании привязки `id`, по [режиму ввода](wiki:options-and-keys#input-modes), который выбрал игрок (нажатие, если не выбран). Клавиша берётся из приложения или из значения по умолчанию в `obsidian.json`. `device` равен `"key"` или `"pad"`, если сработал ввод с контроллера: заданный игроком в приложении, иначе `opts.pad`, функция, которая возвращает, удерживается ли ввод с контроллера этой привязки в текущем кадре. Клавиши сессионного мода ждут лобби с разрешением, а клавиши расширения ждут контента, как и хуки мода. `opts.always` оставляет клавишу в покое, как `obsidian.wrap` делает с хуком, для клавиши, которая действует только на экране этого игрока. `opts.secondary_scope` помещает клавишу в [дополнительную область](#hybrid-scopes) мода.

## Сетевая игра {#multiplayer}

### obsidian.session.cleared(id)

`true`, пока вызывающий мод может работать: в сессии есть разрешение, а для мода с `every_player` его запускает и каждый другой игрок ([Моды, нужные всем игрокам](wiki:session-mods#every-player)). Для расширения `true`, пока идёт контент. Клиентским модам это редко нужно. С id [дополнительной области](#hybrid-scopes) возвращает ответ для неё: всегда `true` для дополнительной клиентской области и `false` для выключенной.

### obsidian.session.guard(t, free)

Представление таблицы `t` для передачи другим модам. Функции из списка `free` работают как обычно. Все остальные отвечают `false, "needs_session"`, когда вызывающий мод работает как клиентский, и `false, "not_cleared"`, когда в сессии нет разрешения ([Как написать библиотеку](wiki:session-mods#libraries)). Расширение, которое их вызывает, получает `false, "not_started"` вне контента и полный доступ к нужным ему библиотекам, пока идёт контент, кто бы ни был в лобби.

### obsidian.session.members()

Список других игроков в лобби. У каждой записи есть `peer`, `obsidian` (запускает ли этот игрок Obsidian), `modset` и `consent` (истина, если этот игрок не блокирует сессионные моды других игроков в публичном лобби).

Чтобы мод работал, только когда он есть у всех игроков, задайте [`every_player`](wiki:session-mods#every-player) в манифесте, а не сравнивайте это самостоятельно.

### obsidian.session.forfeit_progress(), release_progress(key) and hold_progress()

Эти функции ничего не делают. Сохранение принадлежит игроку, поэтому Obsidian не удерживает никакой прогресс миссии, что бы ни делали моды. Функции оставлены, чтобы вызывающие их моды продолжали работать. Заблокированы только отчёты для Галактической войны и таблиц лидеров, пока применён сессионный контент и для миссий, где шёл контент расширения ([Галактическая война](wiki:galactic-war)). Чтобы сыграть так, чтобы миссия не засчитывалась, игрок включает **Заморозить прогресс аккаунта** в [Защите](wiki:guardrails).

### obsidian.guardrails()

То, что игрок выбрал в **Защите** для этого запуска, в виде `{ consent, block_achievements, freeze_progress }`, где `consent` ложно, пока игрок блокирует сессионные моды других игроков в публичном лобби. Мод может их прочитать, например чтобы сказать игроку, что его аккаунт заморожен. Изменить их может только игрок, а загрузчик соблюдает их для всех модов ([Защита](wiki:guardrails)).

### obsidian.war()

Своя война из [Commander](wiki:commander), которую играет этот запуск, в виде `{ id, model }`, где `model` равен `"vanilla"` или `"enhanced"`; `nil` в официальной войне. Сопутствующий мод войны Enhanced читает это, чтобы знать, когда действовать. Сначала проверьте `obsidian.capabilities.war`: в старом загрузчике такого вызова нет.

### obsidian.on_session(fn, opts)

Вызывает `fn(on)` каждый раз, когда загрузчик включает или выключает этот мод, чтобы мод мог отменить то, что увидели бы другие игроки. Мод с `every_player` также узнаёт, когда приходит или уходит игрок без этого мода. Расширение получает `true`, когда контент начинается, и `false`, когда заканчивается, в каждой игре лобби, и то же получает библиотека, нужная только расширениям. С `opts.secondary_scope` `fn` получает только переключения этой [дополнительной области](#hybrid-scopes): клиентская никогда не выключается.

### Гибридные области {#hybrid-scopes}

Мод с [`secondary_scopes`](wiki:manifest#hybrid-scopes) помечает каждую регистрацию дополнительной областью, к которой она относится, последним аргументом `obsidian.hook`, `obsidian.on_frame`, `obsidian.keybind` и `obsidian.on_session`:

```lua
local view = { secondary_scope = "view" }
obsidian.hook("CameraManager", "update", on_camera, view)
obsidian.on_frame(tick_view, view)
obsidian.keybind("toggle_view", toggle, { secondary_scope = "view", always = true })
obsidian.on_session(function(on) if not on then undo_range() end end, { secondary_scope = "weapon_range" })
```

Код дополнительной клиентской области работает в любом лобби, код сессионной только в лобби с разрешением. В расширении код дополнительной сессионной области работает, пока идёт контент, а вне его в лобби с разрешением. В сессионном моде код без пометки следует самой строгой из включённых дополнительных областей; в расширении остаётся с расширением. Выключенная дополнительная область ничего не регистрирует. Код, который выполняется один раз, например скрипт входа и `on_require`, не помечается. Одно состояние Lua обслуживает все дополнительные области, поэтому код в клиентской области может напрямую вызывать сессионный код: ограничиваются только регистрации.

`obsidian.scope()` отвечает `"hybrid"`, пока у сессионного мода включены и клиентская, и сессионная дополнительные области. Вызовы, которые защищает библиотека, считают гибридный мод сессионным, из любой дополнительной области. Старый загрузчик игнорирует `opts.secondary_scope` и управляет всем по основной области, поэтому проверьте `obsidian.capabilities.secondary_scopes`, прежде чем говорить игроку, что личный код продолжает работать. Загрузчики, выпущенные до того, как гибридные области получили это имя, читают `opts.part`, и этот загрузчик тоже его читает.

## Расширения {#expansions}

Для мода с `"scope": "expansion"` ([Как написать расширение](wiki:session-mods#expansions)). Сначала проверьте `obsidian.capabilities.expansion`: в старом загрузчике этого нет.

### obsidian.expansion.start()

Запускает контент вызывающего расширения в игре хоста. Каждый другой игрок в лобби должен запускать то же расширение той же версии с теми же общими значениями параметров. Отвечает `true` или `false` и причиной: `"players_missing"` со списком имён игроков, у которых его нет, третьим значением, `"not_host"`, `"busy"`, пока идёт контент другого расширения, или `"not_expansion"`. Отклонённый запуск также показывает хосту уведомление с именами.

### obsidian.expansion.stop()

Завершает контент в игре хоста. Отвечает `true` или `false` и `"not_running"` либо `"not_host"`. Выход из лобби тоже завершает контент.

### obsidian.expansion.running(id)

`true`, пока в этой игре идёт контент расширения `id`. Без `id` речь о вызывающем моде.

## Текст и журналы {#text-and-logs}

### obsidian.text(key, ...)

Текст `key` из папки `locales` мода на языке игры, с английским как запасным. Дополнительные аргументы заполняют подстановки `%s` и `%d`. Каталог называется по языку: `en.json`, `fr.json`, `es.json`, `pt-BR.json`, `de.json`, `it.json`, `ru.json`, `pl.json`, `ko.json`, `ja.json`, `zh-CN.json`, `zh-TW.json`, `sv.json`, `da.json`, `nl.json`, `fi.json` или `no.json`.

### obsidian.language()

Язык, на котором работает игра, по тем же именам, например `"ru"`. `"en"` для языка, которого Obsidian не знает. В старом загрузчике проверяйте `obsidian.capabilities.language`.

### obsidian.game_text(key, words)

Заставляет игру показывать `words` для одного из игровых текстовых ключей или для ключа, придуманного модом, например названия нового звания. `words` является строкой или таблицей по языкам, например `{ en = "Warden", ru = "Страж" }`, с английским как запасным. `nil` возвращает ключ игре. Для всего остального отвечает `false`. Текст виден только этому игроку, поэтому продолжает работать, пока в лобби нет разрешения. В старом загрузчике проверяйте `obsidian.capabilities.game_text`.

### obsidian.log(...)

Записывает строку в журнал этого мода, в `%APPDATA%\Arrowhead\Helldivers\ObsidianLauncher\logs`.

### obsidian.profiler.start(), stop(), running() and read()

Измеряет, какую часть каждого кадра занимают скрипты каждого мода. `start()` включает измерение для вызывающего мода, пока он не вызовет `stop()`; измерение остаётся включённым, пока его запросил хоть один мод, и немного удорожает каждый вызов мода. `read()` возвращает последний результат, обновляемый примерно дважды в секунду, или `nil` до первого: `{ frame_ms, frames, total_ms, clock, mods = { { id, ms, peak_ms, calls } } }`, самый затратный мод первым. `ms` является средним временем за кадр, `peak_ms` максимумом за один кадр, а `calls` средним числом вызовов за кадр. Время, которое хук проводит в исходной функции игры, засчитывается игре, а не моду. `obsidian.loader` обозначает собственные хуки загрузчика. Страница Script Profiler в окне F6 показывает эти числа поверх игры. В старом загрузчике проверяйте `obsidian.capabilities.profiler`.

## Другие моды и дополнительные файлы {#other-mods}

### obsidian.module(name)

Загружает другой файл Lua этого мода и возвращает то, что он возвращает. Файл должен быть указан в `modules` в `obsidian.json`, а `name` является путём к файлу без `.lua`, например `"lib/parts"`.

### obsidian.import(id)

То, что вернул скрипт `entry` другого мода, или `nil`, если этот мод не работает. Укажите мод в `requires`, чтобы он запускался раньше ([Obsidian API](wiki:obsidian-api)).

### obsidian.scope()

Как вызывающий мод работает в этом применении: `"client"`, `"session"`, `"hybrid"` (сессионный мод с включёнными клиентской и сессионной дополнительными областями, [Гибридные области](#hybrid-scopes)) или `"expansion"`. Библиотека получает `"client"` или `"session"`, а `"session"`, когда она нужна расширению, чтобы библиотека подготовила то, чем может пользоваться расширение ([Как написать библиотеку](wiki:session-mods#libraries)).

### obsidian.caller()

Id мода, чей код сейчас выполняется, чтобы общий мод мог записать, кто что запросил.

### obsidian.info(id)

Что представляет собой работающий мод: `{ id, name, version, scope }`. `name` берётся из `obsidian.json` мода на языке игры, иначе на английском, а `scope` равен тому, что отвечает `obsidian.scope()` в этом моде. Без `id` речь о вызывающем моде. `nil` для мода, который не работает.

## Внутриигровое меню {#menu}

Внутриигровое окно принадлежит Obsidian API, поэтому меняется с релизами API, а новые моды используют `api.menu` ([Obsidian API](wiki:obsidian-api)). Его открывает **F6**, клавиша Obsidian API, которую игроки меняют на вкладке Клавиши мода Obsidian API, а страницы каждого мода лежат в папке с названием мода. `obsidian.menu` оставлен для модов, написанных раньше, и передаёт каждый вызов окну Obsidian API от имени вызвавшего мода. Укажите `obsidian.api` в `requires`: без работающего Obsidian API окна нет, и `open()` отвечает `false`.

### obsidian.menu.add(title, build, opts)

Добавляет страницу в список слева во внутриигровом меню, в папку мода. `title` является текстом или функцией, которая его возвращает. `build(page)` выполняется при каждом открытии страницы. `opts.icon` является одним из `obsidian.ui.glyphs()`:

```lua
obsidian.menu.add("Example Mod", function(page)
  page:header("Tuning")
  page:toggle("Enabled", { get = function() return on end, set = function(v) on = v end })
  page:number("Power", { min = 1, max = 10, step = 1, get = get_power, set = set_power })
  page:choice("Mode", { choices = { { id = "a", label = "First" } }, get = get_mode, set = set_mode })
  page:action("Do it", function() return "Done" end)
  page:input("Name", function(text) end)
  page:page("More", function(sub) sub:label("Deeper") end)
end, { icon = "player" })
```

Любая строка принимает `help`, текст, показываемый, пока она выбрана, и `enabled`, функцию, которая возвращает `false` и причину. Строка, возвращённая действием, показывается всплывающим сообщением. Действие может вызвать `page:refresh()`, чтобы построить страницу заново. Строка со сбоем показывает ошибку и не засчитывается против мода.

Строка `toggle`, `number` или `choice` принимает `default`, начальное значение. Тогда в конце строки появляется кнопка сброса, которая загорается, когда значение изменилось, а R делает то же с клавиатуры. Если запись значения не возвращает прежнее состояние, передайте `reset`, функцию, которая отменяет изменение, и `changed`, функцию, которая сообщает, есть ли что отменять.

Страницы сессионного мода не показываются и закрываются, пока в лобби нет разрешения. Страницы расширения остаются в списке, чтобы контент можно было запустить с одной из них.

### obsidian.menu.open(), close(), toggle(), is_open()

Клавиша Obsidian API открывает окно, как только в нём есть страница, поэтому моду не нужна для этого клавиша. Эти функции нужны моду, который открывает окно в выбранный им момент.

### obsidian.menu.overlay(fn)

Вызывает `fn(draw, width, height)` каждый кадр, чтобы вывести что-то на экран вне меню. `draw.text(text, x, y, color)` и `draw.rect(x, y, w, h, color, alpha)` работают в пикселях от левого нижнего угла. Цвета задаются как `{ r, g, b }`.

### obsidian.toast(text, seconds)

Показывает короткое сообщение в левом верхнем углу экрана или рядом с внутриигровым меню, пока оно открыто. Если работает Obsidian API, сообщение рисует окно API.

### obsidian.notify(text, seconds) {#obsidian-notify-text-seconds}

Показывает `text` в окне подсказок игры, со значком и звуком подсказки, даже если подсказки игры отключены. `seconds` по умолчанию равен 7. Где у игры нет окна подсказок, например в главном меню, сообщение показывается как всплывающее.

Окно показывает одно сообщение за раз, поэтому используйте его для редкого и важного, а `obsidian.toast` для быстрой обратной связи, например на нажатие клавиши. Текст, который уже ждёт, повторно не добавляется, и у мода может ждать до 3 сообщений: сверх этого `notify` возвращает `false` и `"queue_full"`. Сообщения Obsidian идут первыми.

## Замена экранов игры {#ui}

`obsidian.ui` нужен моду, который перерисовывает меню и интерфейс игры. Им может пользоваться любой мод любой области, без чего-либо в `requires`, поэтому новый облик интерфейса остаётся клиентским модом и сохраняет Галактическую войну и подбор игроков. Здесь ничего не работает, пока мод об этом не попросит.

Идея в том, чтобы сохранить логику и ввод игры, остановить её отрисовку, прочитать данные игры и рисовать поверх. Функции обновления и отрисовки игры выполняются всегда, потому что в них живут клавиши, мышь и сетевой код.

```lua
local ui = obsidian.ui
ui.frame(1920, 1080)

ui.on("loadout", {
  mute = true,
  draw = function(kit, data, dt)
    kit:panel{ 120, 140, 1680, 800, cut = 24, corners = "tr bl", fill = "#38383ee0", line = "#ffc433" }
    kit:text("LOADOUT", 960, 880, { font = "heading", size = 48, tracking = 4, align = "center" })

    for i, player in ipairs(data.players()) do
      local panel = data.loadout(player.slot)
      local x = 140 + (i - 1) * 420
      kit:band(x, 780, 400, 40, player.color)
      kit:text(player.name, x + 12, 792, { font = "body_large" })
      if panel then kit:text(panel.ready and "READY" or "PICKING", x + 12, 740) end
    end

    kit:text(ui.prompt("menu_loadout_select"), 140, 150)
  end,
})
```

Если код для экрана даёт сбой, этот экран останавливается до конца сессии, игра снова рисует оригинал, а ошибка попадает в `loader.log`.

### obsidian.ui.current()

Где находится игрок: `{ state, screen, sub }`. `screen` является id, который использует вся эта глава: меню по имени (`"loadout"`, `"armory_profile"`, `"main"`), `"title"` и `"ship"` без открытого меню, `"hud"` в миссии или имя состояния, например `"mission_end"`. `sub` является шагом внутри него, если он есть.

### obsidian.ui.on(id, handlers), off(id)

Выполняет код, пока открыт экран. `id` является значением `screen` или `"*"` для всех экранов.

| Обработчик | Когда |
|---|---|
| `enter(screen)` | Экран появился. Получает то, что возвращает `current()` |
| `draw(kit, data, dt)` | Каждый кадр. `kit` является отдельным холстом, а `data` является `obsidian.ui.data` |
| `exit()` | Экран ушёл |
| `mute` | Не функция: `true` для этого экрана или список id, действует только пока экран открыт |

Обработчики сессионного мода останавливаются, а его заглушения снимаются, пока в лобби нет разрешения. Обработчики расширения продолжают работать вне контента. `off(id)` убирает обработчики вызывающего мода.

### obsidian.ui.mute(id), unmute(id)

Останавливает отрисовку части игры до `unmute`. Логика этой части продолжает работать.

| Id | Что исчезает |
|---|---|
| Имя меню | Это меню: `"loadout"`, `"armory"`, `"options"`, `"mission_briefing"` и так далее |
| `"hud"` | Все части ниже |
| `"hud.panels"` | Панели игроков |
| `"hud.map"` | Карта |
| `"hud.stratagems"` | Список стратагем и перезарядка |
| `"hud.names"` | Имена над игроками |
| `"hud.world"` | Метки на объектах в мире |
| `"hud.prompts"` | Подсказки на объектах для использования |
| `"hud.dialogue"` | Диалоги |
| `"chat"`, `"hints"`, `"samples"`, `"news"`, `"save_icon"` | Каждое из этого |
| `"mission_end"` | Шаги финальных экранов |

Части вложены: заглушение `"hud.panels"` оставляет карту, пока не заглушить и её. Трёхмерные консоли на корабле, карта галактики и вступительный ролик рисуются не так, поэтому остаются. Экран кампании рисует несколько кадров напрямую, и они тоже остаются.

### obsidian.ui.scope(id, target, method)

Добавляет свою часть. После этого `mute(id)` останавливает всё, что рисует эта функция игры: `target` является таблицей или именем глобальной таблицы. Больше ничего не меняется.

### obsidian.ui.data

Копии того, что знает игра, поэтому запись в них ничего не меняет. Каждая функция отвечает `nil`, где она неприменима. `player` является слотом от 1 до 4, а `nil` означает игрока за этой клавиатурой.

| Функция | Даёт |
|---|---|
| `players()` | `name`, `title`, `rank_icon`, `xp`, `color`, `index`, `slot`, `is_local`, `pad` для каждого игрока |
| `loadout(player)` | На экране снаряжения: `items`, `available`, `selection`, `submenu`, `slot`, `ready`, `random`, `loadout`, `presets`, `new_unlocks`, `upgrades` |
| `hud(player)` | `state`, `health`, `shield`, `inventory`, `character`, `stratagems`, `cooldowns`, `respawn`. Таблицы используют имена полей игры |
| `map(player)` | `zoom`, `offset`, `size`, `pings`, `markers` |
| `mission()` | `objectives`, `enemy`, `difficulty`, `environment`, `type`, `seed`, `game_over`, `exit` |
| `campaign()` | `status`, `statistics`, `season`. Данных много, поэтому запрашивайте один раз |
| `mission_end()` | `sub` и `values` со всеми простыми полями состояния |

### obsidian.ui.canvas(id, opts)

Набор для рисования для кода, который не является обработчиком `draw`. `opts.layer` принимает значения от 0 до 875, а `opts.over_fades` сохраняет полную яркость, пока игра затемняет экран. По умолчанию набор затемняется вместе с игрой.

Координаты задаются в пикселях от левого нижнего угла или в пространстве макета мода после `obsidian.ui.frame`. Цвета задаются как `{ r, g, b }`, `{ r, g, b, a }`, `"#rrggbb"` или `"#rrggbbaa"`.

| Метод | Рисует |
|---|---|
| `kit:rect(x, y, w, h, color)` | Прямоугольник |
| `kit:poly(points, color)` | Выпуклую фигуру по `{ x1, y1, x2, y2, ... }` |
| `kit:outline(points, color, width)` | Контур фигуры, изнутри |
| `kit:panel{ x, y, w, h, cut, corners, fill, line, line_width }` | Панель со срезанными под 45 градусов углами. `corners` является любым из `"tl tr br bl"`, по умолчанию `"tr bl"` |
| `kit:hex(x, y, r, color, icon)` | Шестиугольник вокруг точки, со значком внутри, если он передан |
| `kit:glyph(name, x, y, size, color)` | Один из значков, нарисованных фигурами, от левого нижнего угла. `obsidian.ui.glyphs()` перечисляет имена |
| `kit:text(text, x, y, opts)` | Текст. `y` является базовой линией, а перенос строки начинает новую строку. `opts`: `font`, `size`, `tracking`, `align`, `color`, `leading` |
| `kit:measure(text, opts)` | Ширину и высоту текста с учётом разрядки. Ничего не рисует |
| `kit:point(x, y)` | Точку в пикселях, например позицию мыши, в координатах этого набора |
| `kit:icon(name, x, y, w, h, color, uv)` | Одно из изображений игры. `uv` равен `{ u0, v0, u1, v1 }`. `obsidian.ui.icons()` перечисляет имена |
| `kit:art(name, x, y, w, h, color, uv)` | Изображение из материала мода, добавленное через `obsidian.ui.art`. `uv` равен `{ u0, v0, u1, v1 }`, а `u0` больше `u1` отражает изображение |
| `kit:band(x, y, w, h, color)` | Полосу игрока из игры с её градиентом, окрашенную |
| `kit:bar(x, y, w, h, value, color, back)` | Полосу, заполненную от 0 до 1, поверх `back` |
| `kit:clip(x, y, w, h, fn)` | Выполняет `fn(kit)`, ограничивая рисование прямоугольником |
| `kit:layer(n)`, `kit:opacity(a)` | Слой и яркость того, что рисуется дальше |

Глифам не нужна графика, поэтому они работают там, где не работает `kit:icon`. Внутриигровое меню построено из тех же вызовов, поэтому всё, что рисует оно, может нарисовать и мод.

Шрифты: `"body"`, `"body_large"`, `"heading"`, `"heading_large"`, `"ui"`, `"ui_heading"`, `"chat"`, `"debug"`, `"debug_medium"`. `"ui"` и `"ui_heading"` являются шрифтами Barlow и Saira внутриигрового меню и содержат латиницу с диакритикой. `"heading"` является шрифтом Insignia, а `"chat"` содержит китайский, японский и корейский, и к нему переходит текст, когда в выбранном шрифте нет буквы; так показывается и кириллица. `"debug"` не требует загрузки, и все остальные шрифты переходят к нему, пока игра их не загрузит.

Обрезка режет фигуры и значки точно, а текст по целым буквам. Графика меню экрана снаряжения недоступна: материал выгружается между состояниями, а gui, в котором указан незагруженный материал, может остановить игру. Своей графике нужна та же проверка, поэтому холст пока принимает только изображения игры.

### obsidian.ui.font(id, opts)

Добавляет свой шрифт для `kit:text`. `tools/bake_font.py` в репозитории Obsidian превращает файл TrueType в то, что читает игра:

```
pip install pillow uharfbuzz
python tools/bake_font.py --out res --base mymod/fonts title=MyFont.ttf
```

Затем перечислите каждый файл в `resources` манифеста, в загрузочном бандле:

```json
"resources": [
  { "type": "font", "name": "mymod/fonts/title", "bundle": "9cf71054ea26dddf", "data": "res/title.font" },
  { "type": "texture", "name": "mymod/fonts/title", "bundle": "9cf71054ea26dddf", "data": "res/title.texture" },
  { "type": "material", "name": "mymod/fonts/fonts", "bundle": "9cf71054ea26dddf", "data": "res/fonts.material" }
]
```

Добавьте шрифт при запуске мода и используйте его по id:

```lua
obsidian.ui.font("title", { path = "mymod/fonts/title", size = 32 })
kit:text("HELLDIVERS", 100, 200, { font = "title" })
```

`size` является размером текста, который не задаёт свой. Ответ `false` означает, что такого шрифта нет в применении, и текст с ним получает отладочный шрифт. Шрифт должен быть в загрузочном бандле, потому что gui, в котором указан незагруженный материал, может остановить игру. Текст остаётся чётким до размера, в котором шрифт был запечён, по умолчанию 48, а отсутствующая в шрифте буква берётся из `"chat"`. Проверьте лицензию шрифта: запечённый шрифт является изменённой версией, поэтому шрифт с зарезервированным названием не может сохранить это название.

### obsidian.ui.art(name, opts)

Добавляет подматериал материала, который мод поставляет в загрузочном бандле, для `kit:art`. `opts.path` является именем ресурса материала. Ответ `false` означает, что такого материала нет в применении или что новый материал запрошен после того, как игра начала рисовать, поэтому запрашивайте при запуске мода.

### obsidian.ui.list_with(path, with)

Заставляет каждый gui, который создаёт игра и в котором указан материал `with`, указывать и `path`, чтобы игра могла рисовать подматериал `path` там, где рисует подматериалы `with`. `with` по умолчанию равен `"hud/hud"`, материалу со значками званий и стратагем. `path` является материалом, который мод поставляет в загрузочном бандле, а ответ `false` означает, что такого нет в применении. Вызывайте при запуске мода, до того как игра создаст gui. Собирайте много значков в один материал и указывайте его.

### obsidian.ui.frame(w, h), safe()

`frame(1920, 1080)` делает координаты этого мода пространством макета, масштабированным и отцентрированным так же, как это делает игра, по окну и масштабу интерфейса игрока. `frame()` возвращает пиксели. Вызывайте один раз, можно уже при запуске мода. При масштабе интерфейса меньше 1 игра оставляет свободное место внизу окна; `frame(1920, 1080, { centered = true })` держит его посередине.

`safe()` возвращает `{ x, y, w, h, scale }`, область, в которой игра держит свои меню, в координатах мода.

### obsidian.ui.remap_hits(id, fn)

Игра проверяет мышь по тому, где она рисует. Когда макет мода что-то сдвигает, `fn(x, y, w, h)` получает каждый прямоугольник в пикселях и отвечает, где он теперь, `nil`, чтобы оставить его, или `false`, чтобы его нигде не было. `remap_hits(id)` прекращает это.

### obsidian.ui.prompt(name, pad)

Кнопка на устройстве игрока в виде текста для рисования. `name` является действием, например `"select"`, `"back"`, `"fire"`, `"reload"` или `"map"`, токеном, например `"#mod_map"`, или одним из игровых текстовых ключей, который возвращается с подставленными кнопками. `pad` является номером геймпада из `data.players()`, а `nil` означает главного игрока.

## Сохраняемые значения {#storage}

### obsidian.storage.get(key, default), set(key, value), all()

Строки, числа и логические значения, которые этот мод хранит между запусками. `set` с `nil` удаляет ключ. Файл записывается сразу, поэтому не вызывайте это каждый кадр.

### obsidian.save_data.get(key, default), set(key, value), sandbox() {#save-data}

Строки, числа и логические значения, которые этот мод хранит вместе с текущим сохранением, в файле рядом с ним. У каждой [песочницы](wiki:saves) свой файл, а официальный файл переходит вместе с сохранением, когда Obsidian переключает официальные сохранения. Используйте это для того, что принадлежит одному персонажу, например ручного открытия, а `obsidian.storage` для того, что принадлежит установке. `set` с `nil` удаляет ключ, и файл записывается сразу. `sandbox()` является id песочницы этого запуска или `nil` на официальном сохранении. Сначала проверьте `obsidian.capabilities.save_data`: в старом загрузчике этого нет.

Значения, которые игрок должен иметь возможность править в редакторе сохранений, указываются в [ключе `save_editor`](wiki:manifest#save-editor) манифеста.

## Версия и возможности {#version-and-features}

`obsidian.version` является версией API, сейчас `1`. Мод, которому нужен более новый API, задаёт `loader_api` в `obsidian.json`, и старые загрузчики отказываются его запускать.

`obsidian.capabilities` является таблицей только для чтения с тем, что поддерживает работающий загрузчик, по записи на возможность: `hook`, `wrap`, `on_require`, `on_frame`, `on_session`, `after_startup`, `settings`, `keybind`, `input_modes`, `pad_binds`, `session`, `guardrails`, `war`, `scope`, `text`, `log`, `profiler`, `module`, `import`, `caller`, `info`, `menu`, `toast`, `notify`, `storage`, `save_data`, `ui`, `expansion`, `language`, `game_text`, `secondary_scopes` (а также `parts`, старое имя). Проверяйте возможность по имени, прежде чем использовать появившуюся позже:

```lua
if obsidian.capabilities.on_frame then
  obsidian.on_frame(update)
end
```

## Когда мод даёт сбой {#when-a-mod-fails}

- Ошибка при запуске отключает мод на эту сессию и записывает ошибку в `loader.log`.
- Ошибки в хуках и обратных вызовах записываются не более трёх раз на место, поэтому сломанная функция кадра не переполнит журнал.
- Мод, который раз за разом даёт сбой, отключается до конца сессии.
- Если игра вылетает во время запуска мода, приложение назовёт этот мод при следующем запуске.
